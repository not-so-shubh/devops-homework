# Evidence Index

Files in `command-outputs/` are generated by commands actually executed against this repository. They are not hand-written sample transcripts. Timestamps, temporary paths, process IDs, hashes, interfaces, addresses, image IDs, and port selections naturally vary by run.

| Evidence file | Producing command/check | Success signal |
|---|---|---|
| `linux-link-demo.txt` | `linux-fundamentals/link-practice.sh` | Same hard-link inode; expected dangling symlink; final `PASS` |
| `shell-script-output.txt` | Piped-input run of `system-info.sh` | System headings, saved process file, final `PASS` |
| `network-info.txt` | `NETWORK_EXTERNAL=0 networking/collect-network-info.sh` | Available host data plus explicit optional-tool skips |
| `git-practice-output.txt` | `git-github/git-practice-demo.sh` | Untracked-file proof, real selected hash, graph, final `PASS` |
| `docker-environment.txt` | Docker/Compose version checks | Client/server and Compose details, or a truthful blocked reason |
| `docker-fundamentals-build.txt` | Six-service Compose build/start | Real build/start output |
| `docker-fundamentals-curl.txt` | Curl assertions plus Compose `ps` | Six expected Hello World phrases and published ports |
| `docker-multistage-build.txt` | Multi-stage `docker build` | Successful builder/runtime steps |
| `docker-multistage-output.txt` | Run, curl, and filtered `docker ps` | Exact phrase and port mapping |
| `docker-network-output.txt` | Network lab start/inspect/connectivity | Three networks, two positive paths, and frontend/DB isolation |
| `bind-mount-output.txt` | Nginx mount before/after verifier | Initial and updated page from same running container |
| `host-network-output.txt` | Guarded Apache host-network verifier | Confirmed `host` mode and direct port-80 response, or a truthful platform blocker |
| `verification-summary.txt` | Final `scripts/verify-all.sh` run | Totals for PASS, FAIL, and BLOCKED/SKIP |

The Docker files are created only when a Docker runtime is genuinely checked. If Docker is unavailable, `docker-environment.txt` records that limitation and the summary reports Docker checks as blocked; no success files are invented.

Screenshots are intentionally separate from textual evidence. Follow [the screenshot checklist](screenshots/README.md) while real commands/containers are running.

## Privacy review

The process script writes full `ps aux` output only into a temporary test directory; the saved evidence displays a short PID/command-name summary rather than full command arguments. Networking evidence may still contain local interface and resolver information, so review it before publishing the repository publicly.
